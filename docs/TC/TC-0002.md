## Lý Do Thay Đổi (Why)
Thiết lập cấu trúc cơ sở dữ liệu quan hệ PostgreSQL phục vụ lưu trữ dữ liệu vựa hải sản (`merchants`), sản phẩm (`products`), và nhật ký hoa hồng (`referral_logs`) theo định hướng mô hình 3 trụ cột tinh gọn.

## Phạm Vi Thay Đổi (What)
- `.agents/mcp_config.json`: Cấu hình thêm Supabase MCP server.
- `package.json`: Cài đặt thêm dependency `postgres`, `tsx` và các script `db:migrate`, `db:seed`.
- `src/lib/db/client.ts` [NEW]: Tạo database connection client dạng singleton pool.
- `src/lib/db/test-connection.ts` [NEW]: Tạo script kiểm tra kết nối nhanh tới database.
- `src/lib/db/migrate.ts` [NEW]: Script chạy migrations tự động cho Next.js.
- `src/lib/db/seed.ts` [NEW]: Script chèn dữ liệu mẫu.
- `db/migrations/001_create_merchants.sql` [NEW]: Migration tạo bảng `merchants`.
- `db/migrations/002_create_products.sql` [NEW]: Migration tạo bảng `products`.
- `db/migrations/003_create_referral_logs.sql` [NEW]: Migration tạo bảng `referral_logs`.
- `db/migrations/004_enable_rls.sql` [NEW]: Kích hoạt RLS và thiết lập chính sách truy cập.
- `.env.local`: Cập nhật cấu hình kết nối thực tế với mật khẩu được mã hóa.

## Cách Thực Hiện (How)
1. Thêm tables tuân thủ tuyệt đối quy tắc đặt tên (`snake_case`, số nhiều, cột boolean `is_`, timestamp `_at`), cấu trúc khóa ngoại (`merchant_id`, `product_id`), chỉ mục phục vụ truy vấn tối ưu và soft delete (`deleted_at`).
2. Viết di trú Up/Down được bọc trong các giao dịch (`BEGIN; ... COMMIT;`).
3. Dùng thư viện `postgres` làm driver SQL, thiết kế singleton lưu pool vào `globalThis` để Next.js không bị rò rỉ kết nối khi hot-reload trong lúc phát triển.
4. Kích hoạt Row Level Security (RLS) để cô lập bảng, chỉ cấp quyền truy xuất `SELECT` công khai cho `merchants` và `products` thông qua khóa API anon. Bảng `referral_logs` không được cấp quyền công khai nhằm giữ kín nhật ký hoa hồng (chỉ truy xuất qua server-side).
